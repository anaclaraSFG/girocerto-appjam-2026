# Checklist de entrega

## Conteúdo obrigatório

- [ ] Exatamente três páginas/telas identificáveis.
- [ ] Uma única aplicação HTML.
- [x] Nome, RA e e-mail registrados para todos os integrantes.
- [ ] Link público do repositório.
- [ ] Link da aplicação no GitHub Pages.
- [ ] Entrega enviada até o prazo confirmado.

## Experiência e apresentação

- [ ] O problema é compreendido em até cinco segundos.
- [ ] O usuário e o valor da solução estão claros.
- [ ] O fluxo principal conta uma história completa.
- [ ] O antes e depois demonstra impacto financeiro e ambiental.
- [ ] Os dados fictícios estão apresentados de forma responsável.
- [ ] A conexão com os temas estratégicos está clara e consistente.
- [ ] O roteiro da apresentação foi ensaiado.

## Verificação técnica

- [ ] A aplicação abre em navegador moderno sem erros críticos.
- [ ] A navegação entre as três páginas funciona.
- [ ] Os botões usados na demonstração funcionam.
- [ ] O layout foi conferido em celular e computador.
- [ ] Não existem senhas, tokens ou dados pessoais indevidos no repositório.
- [ ] O GitHub Pages foi testado em janela anônima.
- [ ] Os links do repositório e da aplicação foram abertos em outro dispositivo.

## Antes da publicação

- [ ] Escopo do primeiro commit aprovado.
- [x] Conta proprietária e visibilidade do repositório confirmadas.
- [x] Nome do repositório confirmado.
- [ ] Branch principal definida como `main`.

## Antes do envio final

- [ ] Revisar ortografia, nomes e e-mails.
- [ ] Conferir se o repositório está público para a banca.
- [ ] Conferir a versão publicada após o último envio.
- [ ] Guardar uma cópia dos dois links em local acessível ao grupo.
